IMPORTANTE: 

Cada vez que un usuario ejecuta un comando con sudo, el sistema puede dejar constancia en un fichero de registro. En esta práctica activarás ese registro en tu máquina virtual y crearás un script que lo analice con funciones, bucles, comprobaciones y comandos básicos.

PREPARACIÓN: 

En Debian no está habilitado por defecto el fichero /var/log/auth.log, así que activaremos un fichero de registro propio para sudo.

    Edita la configuración de sudo con sudo visudo.

    Añade al final del fichero esta línea y guarda:  Defaults logfile="/var/log/sudo.log"

    Genera actividad: ejecuta al menos cuatro comandos distintos con sudo (por ejemplo sudo ls, sudo apt update, sudo id root) y un intento fallido escribiendo mal la contraseña tres veces.

    Comprueba el resultado con sudo cat /var/log/sudo.log. Solo root puede leer el fichero.

    Cada entrada ocupa una línea con este formato:

Oct  4 22:04:11 : aso : TTY=pts/1 ; PWD=/home/aso ; USER=root ; COMMAND=/usr/bin/ls

Fecha y hora, usuario, terminal, directorio de trabajo, usuario con el que se ejecuta y comando. Los intentos fallidos incluyen además un texto como 3 incorrect password attempts o user NOT in sudoers.

Crea el script sudolog.sh que haga lo siguiente:

    Crea un script Bash llamado sudoinfo.sh que reciba el fichero de registro por parámetro y muestre el siguiente menú.
    Ejemplo de ejecución: sudo ./sudoinfo.sh /var/log/sudo.log

    ---- SUDOINFO ----
    1. Resumen del fichero
    2. Usuarios que han usado sudo
    3. Tres comandos más usados
    4. Intentos fallidos
    5. Entradas de un usuario
    6. Últimas entradas
    7. Guardar un informe en infosudo.txt
    0. Salir

    Condiciones:

        Parámetros por línea de comandos: el script debe recibir exactamente un parámetro con la ubicación del fichero de log.

        Comprobaciones:
        - Si el fichero se ejecuta sin un parámetro. Mensaje de error y termina la ejecución (exit 5).
        - Si el fichero no existe, mensaje de error y termina la ejecución (exit 6).
        - Si no se puede leer el fichero, mensaje de error y termina la ejecución (exit 7)

        Menú:
        - Si se introduce la opción 0, termina la ejecución (exit).
        - Si se introduce otra opción, mostrar "Opción no válida" y volver al menú.
        - Limpia la pantalla cada vez que se muestra el menú y añade una pausa tras cada opción para poder leer el resultado.
        - Se debe crear una función para cada opción del menú que se llamará en la correspondiente opción del case.

        Opciones:
        1) Resumen del fichero: Muestra cuántas entradas tiene el registro, su tamaño y la fecha de la primera y la última. Comandos: wc -l, wc -c, head, tail, cut  
        2) Usuarios que han usado sudo: Muestra cuántas veces ha usado sudo cada usuario, de más a menos. Comandos: cut -d: -f4, tr, sort, uniq -c, sort -nr
        3) Tres comandos más usados: Muestra los tres comandos más ejecutados con sudo, sin sus argumentos. Comandos: grep -o "COMMAND=.*", cut, sort, uniq -c, sort -nr, head
        4) Intentos fallidos: Cuenta los fallos de cada tipo (contraseña incorrecta y usuario fuera de sudoers) y lista las líneas numeradas. Comandos: grep -c
        5) Entradas de un usuario: Pide un usuario y muestra cuántas entradas tiene y cuáles son. Si no aparece, lo avisa. Comandos: read -p, grep -c -F, grep -F
        6) Últimas entradas: Pide cuántas entradas se quieren ver y las muestra. Hay que comprobar que se ha escrito un número. Comandos: read -p, tail -n
        7) Guardar un informe en infosudo.txt Guarda en el fichero un resumen con el resultado de varias opciones, reutilizando las funciones ya creadas. Comandos: { ... } > fichero, date
